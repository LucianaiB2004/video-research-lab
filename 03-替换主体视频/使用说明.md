# 两阶段视频提取与替换使用说明

这套流程建立在第 4 版提示词的证据边界、镜头切分、时间体系、I2V 静动态分工和声音规则上。

## 使用顺序

### 第一次对话：提取原视频

把以下内容一起发送给能够读取完整视频的 AI：

1. 原始参考视频。
2. `第一段-视频蓝图提取.md` 全文。
3. 一句本次要求，例如：

```text
请分析完整视频。待替换目标：画面中的主要人物。
原始提示词输出模式：AUTO。
Prompt 语言：中文。
```

保存 AI 输出的完整 `VIDEO_BLUEPRINT`。不要只保存最后的简短视频 Prompt，因为第二阶段需要主体槽位、互动契约和适配钩子。

### 第二次对话：上传新主体并重构

发送：

1. 第一阶段输出的完整 `VIDEO_BLUEPRINT`。
2. `第二段-替换主体重构.md` 全文。
3. 新人物或新产品的参考图片；多张图片可提供正面、侧面、背面和细节。
4. 可选的原始视频，便于再次核对。
5. 明确的替换映射与输出模式。

人物替换示例：

```text
把 <Source Subject 1> 替换为我上传图片中的人物。
人物替换范围：IDENTITY_AND_APPEARANCE。
服装：保留原视频服装。
原视频镜头、动作、场景、节奏和声音保持不变；只在人体比例或接触关系需要时适配。
输出模式：I2V。
Prompt 语言：中文。
```

产品跨品类替换示例：

```text
把 <Source Subject 1> 的口红替换为我上传图片中的香水。
重构策略：FUNCTIONAL_ADAPTATION。
保留原视频的镜头顺序、运镜、构图、光线、广告节奏和场景。
根据香水瓶真实结构重新设计握持、开盖、按压和喷洒动作，删除口红旋出、涂抹及原品牌元素。
输出模式：I2V。
Prompt 语言：中文。
```

## 输出模式怎么选

- 平台只接受文字：选 `T2VA`。
- 平台接受首帧：选 `I2V`；只有主体身份图时，先把它制作成目标镜头的首帧。
- 需要两套都保存：选 `DUAL`。
- 平台明确支持参考视频编辑或完整视频参考：选 `Ref2VA`。
- 不清楚：选 `AUTO`，同时如实告诉 AI 你所用平台能上传哪些素材。

人物或产品身份的一致性主要依靠参考素材。只有一张正面图时，模型无法从证据中知道背面和不可见结构；多角度、高分辨率、光线清楚且外观一致的素材更适合重构。

## 生成时的实际步骤

如果选择 I2V：

1. 先使用每个 Shot 的 `composited_reference_image_prompt`，结合新主体参考图制作“已经完成替换的首帧”。
2. 检查首帧中的身份、产品几何、构图、手部接触和场景光影。
3. 把这张替换后的首帧与该 Shot 的 `i2v_motion_prompt` 一起提交到图生视频工具。
4. 每个 Shot 分别生成，最后按时间线和 `edit_notes` 拼接。

不能把原人物仍在画面里的首帧直接交给 I2V，再只靠一句“换成另一个人”期待整段稳定替换。首帧锚定了视觉身份，应该先把首帧替换正确。

如果平台原生支持视频编辑或主体替换，可以直接使用 `Ref2VA` 版本及对应素材标签；平台不识别 `<Video 1>`、`<Replacement Subject 1>` 等标签时，应改成该平台真实的素材引用方式。

## 结果边界

这套提示词会尽量提高以下方面的一致性：主体身份、产品几何、动作合理性、接触与遮挡、场景光影、跨镜头连续性和源视频节奏。

提示词本身不能保证“完美嵌入”。最终效果还取决于模型是否支持参考视频、人物或产品一致性、首帧编辑、遮罩、控制轨迹、首尾帧以及单次时长。复杂手部操作、反光透明瓶体、细小 Logo、快速遮挡和大幅视角变化通常需要更好的素材、分镜生成或后期修正。

建议判断成功的标准：

- 新主体在所有镜头中保持同一身份和结构。
- 原主体及其品牌、Logo、专属部件没有残留。
- 新主体自然承接原视频的构图与节奏。
- 握持、接触、遮挡、动作因果和终态合理。
- 光线、阴影、反射、景深和运动模糊属于同一场景。
- 跨品类替换后的动作符合新产品功能。

## XML 系统协议使用方式

- 复制提示词文件中完整的 `<system_protocol>...</system_protocol>`，不要只复制其中一个章节。
- 平台有独立 System Prompt 输入框时，将完整协议放入该输入框；没有独立输入框时，将它作为对话中的第一段指令。
- 保留 XML 标签和 CDATA 边界；本次素材与参数放在独立用户消息，不要逐个替换协议中作为输出示例的占位符。
- 协议交给分析/规划模型；再把它产出的图像或视频提示词及对应素材交给生成工具。XML 标签不会改变消息权限。

第一阶段在尚无目标素材时将 replaceability 标为 PENDING_TARGET，第二阶段再决定直接替换还是功能适配。已有 1.0 蓝图仍可输入，但必须核对来源、范围、主体和事件；缺失信息不能默认视为已确认。
