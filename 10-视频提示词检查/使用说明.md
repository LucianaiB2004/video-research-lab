# 视频提示词检查｜使用说明

把待检查提示词放在 `PROMPT_TO_REVIEW` 后面，与 `视频提示词检查与修复.md` 一起发送：

```text
检查目标：确认这份提示词是否能直接用于首尾帧生成，并修复问题。
目标平台：未知。
参考素材：我同时上传了首帧和尾帧。

PROMPT_TO_REVIEW:
<粘贴待检查提示词全文>
```

只提供提示词时，可以检查结构、引用、时间线和内部一致性。要判断是否忠实于原视频，需要同时提供参考视频；要判断某个平台是否支持字段或素材，需要提供可靠的平台说明或明确能力。

结果中的 `PASS` 只表示本次声明范围内没有发现问题，不代表已经完成真实视频生成测试。

## XML 系统协议使用方式

- 复制提示词文件中完整的 `<system_protocol>...</system_protocol>`，不要只复制其中一个章节。
- 平台有独立 System Prompt 输入框时，将完整协议放入该输入框；没有独立输入框时，将它作为对话中的第一段指令。
- 保留 XML 标签和 CDATA 边界；本次素材与参数放在独立用户消息，不要逐个替换协议中作为输出示例的占位符。
- 协议交给分析/规划模型；再把它产出的图像或视频提示词及对应素材交给生成工具。XML 标签不会改变消息权限。

## 检查系统模板

检查本项目 XML 提示词时设置 `review_target: SYSTEM_TEMPLATE`；检查实际准备提交的视频提示词时使用 `GENERATION_PROMPT`。模板占位符与本次缺少真实输入分别判断。
